Runtime UI

RmlUi is the production UI path

Author normal .rml documents and .rcss stylesheets inside the project, then drive semantic UI state from gameplay code.

RmlUi

Vespera 1.0 integrates pinned RmlUi 6.2 with FreeType. RML documents participate in the asset catalog, stable startup UI references, build closure, controlled moves, Editor Play, and standalone runtime.

Project-owned UI

The project can name a stable startup RML asset. Linked RCSS files stay project-owned and are included when required by the build closure.

C# bridge

C# uses the semantic UiSurface/UiElement API to find elements, read button state, change text, and set style properties without depending on engine internals.

var score = UI.Find("score");
if (score is not null)
    score.Text = "Score 10";

var player = UI.Find("player");
player?.SetProperty("left", "128px");

Using UI as a 2D canvas

The experimental 2D starter uses positioned RmlUi elements for the playable field while C# owns movement and state. This is a supported foundation for screen-space game designs, not a claim that 1.0 has full orthographic world authoring.

1.0 limits

  • One active RmlUi surface per process.
  • No dedicated visual RML/RCSS layout editor.
  • Legacy .slui remains for compatibility/QA.
