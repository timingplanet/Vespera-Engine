Gameplay

C# first, Lua where it fits

Vespera's primary gameplay layer is project-owned C#. Lua is a smaller project-level runtime/mod path.

C# components

Starter projects ship their own managed project. Components derive from Vespera.Component, can expose fields to the Inspector, and use the public Entity, Transform, Input, Physics, Assets, Audio, Prefab, Scene, SaveData, and UI APIs.

using Vespera;

public sealed class PlayerController : Component
{
    [Expose("Move Speed")]
    public float MoveSpeed = 5.0f;

    public override void Update(float dt)
    {
        var x = Input.Value("move_horizontal");
        var y = Input.Value("move_vertical");
        Transform.Position += new Vec3(x, 0, y) * MoveSpeed * dt;
    }
}

Lifecycle

The managed component path supports the normal component lifecycle, including startup/update and enable/disable/destroy behavior. Scene changes and Play/Stop restoration are part of the release-candidate QA coverage.

Gameplay API

Common systems include entity/component access, prefab spawning, collision/trigger queries, raycasts, input actions, audio, save data, scene switching, stable asset references, and RmlUi through UiSurface.

Lua

Lua 5.4.9 is optional and intentionally smaller. A project may configure one stable Lua entry with optional Start(), Update(dt), and Stop() functions. C# remains the full-game scripting path.

Per-entity Lua components, require/package modules, and a Lua-specific event bus are not 1.0 features.

Compiler errors and last-good output

Vespera keeps the last-good managed output when a C# build fails, reports compiler diagnostics, and can rebuild/reload after the source is fixed. The RC QA gate deliberately injects and recovers from a managed compiler error.

For the complete API details, use the repository docs linked from Reference.
