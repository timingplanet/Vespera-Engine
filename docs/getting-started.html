Getting Started

From source to Play Mode

The normal Vespera workflow starts in the Project Hub. New game developers should not need the internal QA or automation scripts.

Requirements

  • Windows x64.
  • A Direct3D 12-capable GPU.
  • Visual Studio 2026 / MSVC with C++ desktop tooling and the Windows SDK.
  • .NET 8 SDK for project C# compilation.

Build Vespera

Set-ExecutionPolicy -Scope Process Bypass
.\build.ps1
.\vespera.ps1

The first build fetches the pinned third-party dependencies and takes longer than later incremental builds.

Choose a template

TemplateUse it for
3D / 2.5D GameThe primary 1.0 starter: sector-world authoring, project C#, collision, lighting, sprites, and optional mesh content.
2D / UI Foundation (Experimental)Screen-space games driven by RmlUi + C#, including card, board, puzzle, HUD-heavy, and UI-centric projects.
Empty ProjectA minimal scene and project-owned C# bootstrap when you want to assemble the project yourself.

Enter Play Mode

Open your project in the editor and press Play. Vespera runs the project through the same gameplay services used by standalone builds. Stop returns to the saved edit state.

About the 2D foundation

The 2D starter is deliberately different from the 3D starter: its RmlUi document is the game canvas and its C# component moves a player, handles a goal, score, reset button, and input actions. It demonstrates a useful 1.0 screen-space workflow without pretending the editor has a finished orthographic world mode.

Dedicated orthographic world rendering/editor tooling and a complete 2D physics workflow are not part of 1.0.
